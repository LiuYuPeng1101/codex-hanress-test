# 订单分析 Skill

处理订单相关任务时必须遵守以下规则：

1. 从用户请求中识别业务订单 ID；无法确定时先向用户确认，不得猜测。
2. 任何实时订单状态、履约信息、预计送达信息都必须通过订单 MCP Tool 从真实业务系统获取。
3. 不得把模型推断、历史记忆或静态文档当作实时订单事实。
4. 明确区分“业务系统返回的事实”和“基于事实做出的分析”。
5. 对取消订单等写操作，只能调用受治理的 MCP Tool，不得尝试通过本地文件、脚本或其他旁路修改业务状态。
6. 如果写操作进入 Approval，等待宿主应用的审批结果；被拒绝时不得绕过审批再次执行等价操作。
7. 不在回答中泄露 Tool 原始敏感参数、服务凭据、内部鉴权信息或 Runtime 私有事件。
8. 最终使用简洁、明确的中文说明当前事实、已执行动作、未执行动作以及需要用户进一步确认的事项。
